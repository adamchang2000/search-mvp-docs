---
title: "Errors"
description: "The error shape, and what every error code means."
---

Every error has the same JSON shape, whatever the status:

```json
{
  "error": "rate_limited",
  "code": "rate_limited",
  "message": "rate limit of 60 calls/minute reached",
  "retryable": true,
  "retry_after_seconds": 2.5,
  "request_id": "req_…"
}
```

Branch on `code` (stable) and `retryable`; `message` is for people and models and may change. `details`
appears when there's more to say, e.g. validation errors as `{"errors": [{"path", "message"}]}`.

| Status | `code` | Retryable | Meaning |
|---|---|---|---|
| 400 | `invalid_request` | no | A parameter is out of range or malformed. |
| 401 | `unauthorized` | no | Missing, unknown or revoked API key. |
| 413 | `record_too_large` | no | The feedback record is over 64 KB ([size limits](/limits#size-limits)). |
| 422 | `invalid_request` | no | The body doesn't match the schema (`details.errors` says where). |
| 422 | `invalid_record` | no | A feedback record is malformed or cites a source we can't find. It was stored. See [Source disagreements](/feedback/source-disagreements#invalid-records). |
| 422 | `fetch_failed` | no | The page couldn't be read: the site blocked it, it doesn't exist, or it has no readable text. |
| 429 | `rate_limited` | yes | Over your [rate limit](/limits#rate-limits); wait `retry_after_seconds`. |
| 500 | `internal_error` | yes | Our bug. Retry, and tell us the `request_id` if it persists. |
| 503 | `upstream_rate_limited`, `overloaded` | yes | Busy; retry after `retry_after_seconds`. |
| 503 | `upstream_error`, `upstream_unreachable`, `upstream_bad_response` | usually | The search backend failed or couldn't be reached. |
| 503 | `upstream_timeout`, `request_timeout` | yes | The search backend, or the whole request, took too long. |
| 503 | `upstream_out_of_credits` | no | Search is temporarily unavailable on our side. |

Over MCP the same errors reach the model as a tool error with the `message`, so it can decide to retry,
rephrase, or move on.
